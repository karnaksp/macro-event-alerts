# Приёмочные сценарии будущего runtime

Таблица задаёт целевые проверки всего сервиса. Выполненные проверки P1 перечислены в `docs/p1-verification.md`; live adapters и Telegram failures ещё не проверены. Contract validator и pytest выполняют разные части проверки.

| Ситуация | Ожидаемый результат runtime |
| --- | --- |
| Первый запуск на уже опубликованной истории | Baseline без Telegram-рассылки истории |
| Повтор одного ответа, включая перезапуск | Одно логическое событие; состояние и outbox сохранены |
| Принято A→B→A→B | Три отдельных перехода; хеш значения не стирает событие |
| Прогноз null→3.0 | Инициализация прогноза, без `macro.forecast_changed` |
| Прогноз 3.0→3.1 до публикации | Изменение того же источника/серии/периода |
| Прогноз поменялся после выхода actual | Без нового алерта о дорелизном прогнозе |
| Новый период, actual равен прошлому | Новый `macro.release` |
| Изменился опубликованный actual | `macro.revised` с периодом пересмотра |
| Изменился previous без известного периода | Контекст выпуска, без выдуманной revision |
| Поздний снимок с меньшей source revision | Карантин/история; baseline не откатывается |
| Смена поставщика, единиц, MoM/YoY, horizon или outcome | Новый baseline вместо ложного изменения |
| Цена исхода 0.55→0.75 | +20 п.п.; один и тот же контракт, источник и price basis |
| Цена 0.55→0.64→0.75 в одном окне | Алерт с оконным +20 п.п.; outbox сохраняет evaluation context, cooldown подавляет частые повторы |
| Спред/ликвидность не прошли фильтр, цена устарела или placeholder | Нет scenario-алерта; причина видна в диагностике |
| Источник вернул пустой/битый ответ | Сохранённый baseline остаётся; ошибка источника зарегистрирована |
| Crash до/после commit snapshot/event/outbox/checkpoint | Replay не теряет событие и не продвигает курсор преждевременно |
| Telegram HTTP 200 с `ok:false` | Запись не считается доставленной |
| Telegram 429 с retry_after; 5xx | Отложенный повтор с backoff |
| Telegram 401/403 | Terminal failure и диагностика без бесконечных повторов |
| Timeout после возможного принятия Telegram | Пометка ambiguous; возможный дубль описан оператору |
| Рестарт контейнера / SIGTERM | Состояние в volume, очередь продолжает работу |

Для каждого адаптера сохраняется обезличенный raw fixture с URL, временем получения, маппингом полей и измеренной задержкой, если время публикации известно. Live Telegram smoke test выполняется только после задания пользователем тестового чата; в задаче планирования сообщения не отправляются.
